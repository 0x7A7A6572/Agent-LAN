## .research 反复入库的根因与处理

- 现象：`.gitignore` 第 8 行已有 `.research/`，但 `git ls-files` 里仍有 24 个 `.research` 文件。
- 根因：**tracked-before-ignore**。`.research/tmp/fake-agent.cjs` 在初始提交 `4a42a5b` 就已入库；git 的 ignore 规则对已跟踪文件无效，所以后续 `git add` 会一直带上。之前几次 `git rm` 只删了索引，忽略规则依然不生效，于是又回来。
- 处理：`git rm -r --cached .research` → 本地文件全留 → 提交 `c3339de chore: .research 全部取消跟踪，仅保留本地`。索引中 `.research` 归零，ignore 真正生效。
- 历史未清洗：`git log -- .research` 仍可翻出 30 个路径（约 10 个提交，含初始提交）。用户选择「就此为止」，不做 filter-repo 重写，避免 130 个提交哈希全变 + 强推。
- 结论：以后处理这类「明明 ignore 了还在提交」的问题，先查 `git ls-files | grep <path>` 判断是否已被跟踪，而不是怀疑 ignore 规则写错。

## DeepSeek Harness 启动崩溃：profile package.json 被写了 BOM（11:50）
- 现象：弹窗「The application could not start or stopped unexpectedly / Unexpected token ','… is not valid JSON」，崩在 `phase: startup`。11:37、11:49 各崩一轮，共 6 个 crash log。
- 根因：`~/.dsh/profiles/desktop/package.json` 开头有 **UTF-8 BOM（`EF BB BF`）**，`JSON.parse` 不认。栈指向 `@deepseek-ai/dsh-app-boot` 的 `readProfileManifest` ← `loadProfileDirectory` ← host `main`。**`readProfileManifest` 读的就是 profile 的 package.json**（报错内容以 `{"name"` 开头是判断依据）。
- 修复：备份 `package.json.bom-bak-1792641201` → 剥 BOM 后原样写回 → `JSON.parse` 校验通过（name=@deepseek-ai/dsh-desktop-runtime，8 deps / 19 bundles）。其他 `.dsh` 下 JSON 无 BOM。
- 文件 mtime 11:36，正好在首次崩溃前 1 分钟；`local-plugins/*.tgz` 是 10-21 的，不是插件安装写的。**Windows 侧用 PowerShell 5.1 的 `Set-Content`/`Out-File -Encoding UTF8` 改这个文件必带 BOM**，以后再手工/脚本改 `~/.dsh/profiles/*/package.json` 要用 `[IO.File]::WriteAllText($p,$s,(New-Object Text.UTF8Encoding $false))` 或 Node `writeFileSync(p,s,'utf8')`。
