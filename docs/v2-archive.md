## 1.0 是什么，为什么不够

1.0 是「A2A 通信总线 + 工单系统 + PM 提示词」：

    A2A 跨机器层      Agent Card 发现 / Task 状态机 / Artifact 文件
    本机适配层        每台机器一个 adapter
    工单系统          状态、处理人、依赖、timeline
    PM                一份 pm.md 提示词 + 控制台文本框

失败点不在功能，而在于**「谁来决定下一步」这件事从未落到代码里**：

1. 角色只是 Map 里的字符串，没有任何代码读它
2. `by` 参数由调用方自报，任何节点都能冒充 PM
3. 派发不经过中枢，`mac_send_task` 可随意绕过工单
4. PM 用 worker 拉活，退出即失忆，无法持续盯进度

前作设计文档当时主动划掉了权限（"不做角色权限隔离，靠约定"），
这一步决定了 PM 只能是提示词。2026-10-19 已整体退役（3f91cb5）。

## 2.0 是什么

回到最初目标：多 agent 设计模式中的 **Supervisor 模式**，以局域网 agent 的方式实现。

三条原则：

1. **调度与通信分离**：调度控制流 Supervisor 独占，通信数据流直接放行
2. **派发权属于 hub**：PM 只是临时持有者，不是被赋权的实体
3. **拦截有边界**：留言放行、新任务派发拦截、同工单内返工豁免

设计文档：`2026-10-19-supervisor-hub-design.md`
